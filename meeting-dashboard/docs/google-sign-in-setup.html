Enable Google account sign-up

The dashboard now supports Google Identity Services. First-time and returning users use the same Google button. Google verifies their identity; each person then connects their own Cal.com account. No Cal.com credential is shared across users.

Required owner setup

  1. Open Google Auth Platform → Clients in a Google Cloud project you control.
  2. Configure the app branding and audience. For people outside your organization, use an External audience. Testing mode may restrict access to your listed test users; configure production availability when ready for general sign-up.
  3. Create an OAuth client with application type Web application.
  4. Under Authorized JavaScript origins, register exactly:
    https://meetingschedule-hub-nov26.dragonwarrior9873.chatgpt.site
  5. Copy the client ID, ending in .apps.googleusercontent.com, and supply it to the dashboard administrator. It is a public identifier, not a secret. A client secret is not required by this popup-based Google Identity Services flow.
  6. Set the Site environment variable GOOGLE_CLIENT_ID to that ID, then redeploy the saved version to apply the environment change.
  7. Set the Site audience to public so visitors can reach the sign-up page. Scheduling APIs still require an authenticated Google or existing Sites identity and that user's Cal.com session.

What users do

Open the dashboard → Continue with Google → select their account → connect their own Cal.com API key → schedule meetings. The first Google sign-in establishes a stable identity based on Google's subject identifier. The app does not require a password or store a separate user-registration database. Meetings remain in Cal.com.

Privacy and verification

The backend verifies Google's token signature, issuer, audience, expiry, nonce, and verified email. Login challenges expire after ten minutes. The resulting secure HttpOnly session lasts eight hours. Changing accounts clears the previous Cal.com connection. Signing out clears the identity and Cal.com cookies. Google sign-in alone does not grant Google Calendar access or create a Cal.com account.

Without a configured client ID, the page explains that Google sign-up is awaiting setup. Automated tests cover authentication failures and cross-user isolation. Real Google authorization needs the registered client and an actual user login; it cannot be verified with mock responses.
